# Cyclone Scan — Device Trust

Bank-grade Android device verification: is this a genuine, unmodified phone
running the real app?

**The phone collects evidence; the server decides.** Trust rests on
hardware-signed evidence (Android key attestation, checked against Google's
roots and revocation list) plus Google Play Integrity, never on checks that
run only inside the app.

| Folder | What |
|---|---|
| [`service/`](service/README.md) | Python verifier and HTTP API: key attestation, revocation list, Play Integrity, attested device identity. Makes the ALLOW / BLOCK decision. |
| [`android/`](android/README.md) | Kotlin client library (`:devicetrust`) that creates the attested key, fetches a bound Play Integrity token and enrolls. |
| [`android/scanner/`](android/scanner/README.md) | **Test APK**: scans the phone it runs on and shows the verdict, score and every check; also runs the biometric and full server flows. |
| [`testvectors/`](testvectors/) | Risk-engine vectors generated by the server and replayed by the on-device engine to keep both in lockstep. |

## Roadmap

1. **Phase 1 (done):** enrollment with hard-fail gates.
2. **Phase 2 (done):** device binding: sensitive actions signed with the enrolled hardware key; biometric-bound confirm key for high-risk actions; device revocation.
3. **Phase 3 (done):** client RASP signals (root, hooking, emulator, tampering, scam/remote-control indicators) and an explainable server-side risk score with an audit trail.
4. **Scanner APK (done):** on-device demo/test app (`android/scanner`).
5. **Run 6 (done):** attestation provenance (Google RKP vs factory keybox), fleet-wide leaked-keybox detection, hardware-vs-reported patch/OS spoofing checks.
6. **Run 12 (done):** fleet intelligence: network-block and cohort bursts (privacy-preserving keyed hashes), many devices per network, Play Integrity device recall, admin fleet view.
7. **Run 13:** native own-process collector, native/Kotlin comparisons and honest coverage reporting; see [run notes](docs/RUN_13_NATIVE.md).
8. **Run 14:** typed coverage for every Kotlin check (detected / clean / could not verify / unsupported), strict server validation, scanner "Verification coverage" card and versioned export; see [run notes](docs/RUN_14_REPORT_COVERAGE.md).
9. **Next delegated runs (see [build log](docs/BUILD_LOG.md)):** 15 verifier compatibility, 16 device lifecycle, 17 server-verified scan and history, 18 beta packaging, 19 device validation and beta candidate. Normal-phone smoke tests should start as soon as a test device is available.

## Quick start

```bash
python -m pip install -e 'service[test]'
python -m pytest -q service/tests

cd android && ./gradlew :devicetrust:testDebugUnitTest :devicetrust:assembleRelease
```

Physical-device verification has not been done yet; see each folder's README.
