Cyclone Scan 0.9.0-dev.3 (scanner versionCode 8). Apache-2.0.

This release fixes the problems found in the first on-device run of 0.9.0-dev.2 (Pixel 8, Android 16, 18 October 2026). Every fix has a test written before the change.

### Fixed
- **A false "no accessibility service" result.** The check now also reads the `enabled_accessibility_services` setting. An empty list from AccessibilityManager shortly after launch no longer reads as "none enabled" (SDK `AccessibilityServices`).
- **A transient revocation failure no longer blocks by itself.** The Google revocation list is retried for network-level failures (two retries, 0.4 s and 1.2 s apart). The list is saved after each live download. If every live attempt fails and a copy from the last 24 hours exists, the scan uses it and says so in the report and the layer detail ("live download failed; checked against a copy saved within the last 24 hours"). Without a live list or a recent copy, revocation stays unestablished, as before.
- **Hook checks no longer read "absent" from one process.** Frida, Xposed/LSPosed and Zygisk inject only into the processes they target. The scanner can only read its own process, so a NOT_DETECTED result is now reported as "could not verify" with reason `SCOPE_LIMITED`. A detection is still reported as a detection. The reason code is added to the Kotlin and Python vocabularies together.
- **A missing native reason is explained.** The native collector sends no reason for some checks (SELinux permissive). The report now says so and points at the Run 27 native review. **The native code is unchanged in this release**, as required.
- **The native-versus-Kotlin row shows counts.** It replaces "Equivalent observations disagree", which read like a disagreement when none was found. It now states the matched, disagreeing and not-comparable counts.
- **The biometric message says which cause applies.** It separates "no screen lock is set", "no strong fingerprint or face is enrolled", "no strong biometric sensor" and "enrolled, but the key could not be created".
- **The Server tab no longer pre-fills a placeholder address.** The stored placeholder `192.168.1.10` is treated as empty. The field shows `http://<computer-ip>:8080` as a hint.

### Test-environment fixes (service tests on Windows)
- `docs/validation/**` is stored without line-ending conversion (`.gitattributes`), so the committed evidence keeps its hashes on a Windows checkout with `core.autocrlf=true`.
- The fake `apksigner` used by the signing test runs as a `.cmd` file on Windows.
